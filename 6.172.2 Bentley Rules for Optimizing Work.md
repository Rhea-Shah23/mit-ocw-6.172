**What is Work?**
- Sum total of all the operations executed by the program
- Algorithm design can reduce the amount of work it takes to solve a problem 
- Reducing work of a program does not automatically reduce running time 
	- Due to complex nature of computer hardware 
- Reducing work serves as a good heurisitic for reducing overall running time

*Data Structure Optimization*
- Packing and Encoding
	- Packing: store more than one data value in a machine word 
	- Encoding: convert data values into a representation requiring fewer bits 
	- Need less memory fetches 
	- Requires more work but takes less space
	- Sometimes unpacking and decoding are the optimization, depending on whether more work is involved moving the data or operating on it 
- Data Structure Augmentation 
	- Add information to a datastructure to make common operations do less work
- Precomputation
	- Perform calculations in advance to avoid doing them at "mission-critical" times
	- ex: lookup table
- Compile-time intialization
	- Store the values of constants during compilation, saving work at execution time
	- Idea (2): Create large static tables by metaprogramming 
		- Have a program to write your program
- Caching
	- Store results that have been accessed recently, so that the program does not have to recompute 
- Sparsity
	- Avoid storing and computing on zeros 
	- "The fastest way to compute is not to compute at all"
	- Compressed Sparse Row (CSR) datastructure

*Logic Optimizations:*
- Constant Folding and Propagation
	- Evaluate constant expressions and substitute to result into further expresses during compilation (avoid doing it at runtime)
- Common Subexpression Elimination
	- Avoid computing same expression multiple times by evaluating the expression once and storing result for later use 
- Algebraic Identities
	- Replace expensive expressions with algebraically equivalent that require less work
- Short-Circuiting
	- When performing a series of test, stop evaluating as soon as you know the answer
	- Ordering Tests: perform tests that are more often successful earlier, inexpensive tests should precede expensive ones
- Create a fast path
- Combining Tests
	- Replace a sequence of tests with one test or switch

*Loop Optimization*
- Hoisting
	- Avoid recomputing loop-invariant code each time through the body of a loop
- Sentinels
	- Dummy values placed in a data structure to simplify the logic of boundary conditions and handling loop-exit tests
- Loop Unrolling (not common)
	- Full Loop Unrolling: All iterations are unrolled
	- Partial Loop Unrolling: Several are unrolled
- Loop Fusion
- Eliminating Wasted Iterations
	- Modify loop bounds to avoid executing loop iterations over essentially empty loop bodies

*Function Optimization*
- Inlining
	- Avoid overhead of function call by replacing a call to the function with the body of the function itself
- Tail-Recursion Elimination
	- Replace a recursve call that occurs as the last step of a function with a branch, saves function-call overhead 
- Coarsening Recursion
	- Increase size of base case and handle it with more efficient code that avoids function-call overhead

**Closing**
- Avoid premature optimization
	- 1st: get working code 
	- 2nd: optimize & preserve correctness (regression testing)
- Reducing the work of a program does not necessarily decrease its running time 
- Compiler automates many low-level optimizations 
- To tell if compiler is actually performing an optimization, look @ assembly code
